# Roadmap and GitHub issue hierarchy

The [CSS roadmap](https://github.com/RoboXGamer/SolidNativeZigExperiment/issues/383) organizes **148 open CSS catalog issues** by what each phase lets you build. The published tree has one roadmap, three phase trackers and 15 category trackers. The existing runtime workstreams have their own trackers.

## Where to start

- **Phase 1 brings together core app styling.** Build a real settings or dashboard screen from ordinary CSS with flexible sizing, stylesheets, surface styling, text, interactive states and responsive themes. [#384](https://github.com/RoboXGamer/SolidNativeZigExperiment/issues/384)
- **Phase 2 adds richer interfaces.** Use local font assets, component-sized layouts, richer selectors and generated content, more color and image controls, and motion. [#391](https://github.com/RoboXGamer/SolidNativeZigExperiment/issues/391)
- **Phase 3 covers advanced CSS and native equivalents.** Scope complex formatting, filters and compositing, advanced transitions, and host-specific behaviors. [#398](https://github.com/RoboXGamer/SolidNativeZigExperiment/issues/398)

## Keeping the roadmap current

Put new work under the earliest phase whose app exercise needs it, then pick the category that owns its implementation. Keep one direct parent and link related work across categories. Review actual prerequisites at the feature-slice level before adding a GitHub blocker. Store conformance evidence on the leaf so the roadmap remains useful even when several phases share one subsystem.

The live graph was verified after publication. All 148 existing CSS leaves point to the intended category, all category trackers point to the intended phase, and all three phases point to the roadmap. Issue states, titles, existing blockers and unrelated parents matched the pre-change snapshot.
