# Positioning acceptance evidence

Issues #1, #86 and #155 are implemented for the tracked slice and linked for closure on merge. This document records implemented native paths and executed regression evidence; it does not certify exhaustive browser/WPT conformance.

## Completion follow-up

Final validation: `zig build test --summary all` passed **124/124** tests. `pnpm run test`, eight native framebuffer checks, `pnpm run build:ui`, `zig build`, and native smoke (19 scene items) passed. The older 113-test figure below records the earlier checkpoint.

- Block and inline static positions now come from the block layout cursor and margin strut, so a relatively shifted sibling does not displace an absolute child's hypothetical position.
- Positioned grid children resolve explicit positive/negative/named lines, line spans and named grid areas without participating in track sizing or auto-placement. RTL static placement uses the selected area's width.
- Perspective ancestors establish fixed containing blocks consistently with transforms, including scroll participation through intermediate static ancestors.
- Horizontal and vertical automatic margins now resolve negative free space correctly, with the horizontal overconstraint direction taken into account.
- Logical border axis/side shorthands, width/color/style longhands and kebab-case names map before snapshot. Native widths resolve thin/medium/thick; none/hidden remove geometry; solid/double/dotted/dashed/groove/ridge/inset/outset reach per-side raster painting with currentColor/transparent color handling.
- Logical margins/padding retain percentage values until native resolution; their physical consumers use the containing block width for percentage bases. Logical sizing continues through the native intrinsic/min/max sizing paths.
- JS tests exercise logical side and axis mapping in all five writing modes with LTR/RTL, shorthand resets, naming forms, invalid border styles/widths and reactive inherited-direction changes. Native geometry/raster tests exercise the actual consumers.

Rules used for the fixtures: [CSS Logical Properties Level 1](https://drafts.csswg.org/css-logical-1/) and [CSS Positioned Layout Level 3](https://drafts.csswg.org/css-position-3/). These include specification-derived regressions and 66 frozen Edge geometry/radius comparisons; the full WPT suite was not executed. Platform-specific border bevel shades and rounded dash distribution are renderer choices.

## Direct implementation follow-up

- Auto-width absolute boxes now subtract a definite left/right inset before applying `min(max-content, max(min-content, available))`. Intrinsic minimum overflow is retained.
- Auto-inset block children use the parent content origin and preceding in-flow sibling's trailing edge rather than the containing block origin. Absolutely positioned siblings do not consume flow space.
- Flex static placement uses sole-item main/cross alignment for the covered horizontal writing-mode cases.
- Fixed descendants of transformed scroll containers now receive the transformed container's own scroll offset; viewport-fixed descendants retain their scroll independence.
- Six native geometry regressions cover these changes and transformed padding-box placement. JS fixtures cover both inset naming forms, all five writing modes in LTR/RTL, zero/auto/negative/percentage values and declaration order.
- Final checks: `zig build test --summary all` passed 113/113; `pnpm run test`, `pnpm run test:native` (eight framebuffer checks), `pnpm run build:ui`, `zig build`, and `pnpm run test:smoke` passed (19 scene items).

The completion follow-up above supersedes the former missing inline/grid, margin-strut, perspective and logical-border implementation paths. Inset geometry evidence must not be attributed to border styles named `inset`; border styles now have their own raster evidence.
